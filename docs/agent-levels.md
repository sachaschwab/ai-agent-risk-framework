# Agent Levels

Use these levels to classify systems by behavior, not by vendor branding.

## Level 1: Knowledge Assistant

Answers questions from selected knowledge sources.

Typical examples:

- Internal policy assistant
- Documentation Q&A assistant
- FAQ copilots with no tool execution

Main governance focus:

- Source quality and freshness
- Access permissions
- User disclaimers and escalation guidance

## Level 2: Guided Workflow Assistant

Supports a user through a task, while the human remains decision-maker.

Typical examples:

- Draft response assistants
- Meeting brief builders
- Next-step recommendation assistants

Main governance focus:

- Human review quality
- Source transparency
- Workflow boundary definition

## Level 3: Tool-Using Agent

Can call tools, APIs, connectors, or flows.

Typical examples:

- Ticket creation agents
- CRM lookup and update helpers
- Workflow invocation agents

Main governance focus:

- Tool permission matrix
- Least privilege
- Audit logging and approval policy

## Level 4: Autonomous Workflow Agent

Acts on triggers and executes process steps without waiting for each user prompt.

Typical examples:

- Exception routing agents
- Alert triage and enrichment agents
- Automated reconciliation agents

Main governance focus:

- Trigger validation
- Action boundaries
- Human approval for high-impact actions
- Runtime monitoring and kill switches

## Level 5: Multi-Agent Orchestration

Multiple agents coordinate, delegate, and hand off work.

Typical examples:

- Cross-functional onboarding orchestration
- Multi-agent incident response workflows
- Procurement process orchestration

Main governance focus:

- Agent identity and delegation policy
- End-to-end traceability
- Accountability and ownership model

## Practical rule

Do not govern labels. Govern behavior.
